## 一句话介绍

QueryForge 是一个可治理的 AI 数据分析平台，将原始数据接入、质量校验、增量发布、语义建模和自然语言转安全 SQL 串联为一条可观测、可审计的分析链路。

## 简历详细版

### QueryForge——可治理的 AI 数据工程与 NL2SQL 平台（二次开发）

项目背景：传统 NL2SQL 工具通常只关注 SQL 能否生成，容易忽略原始数据质量、业务口径、安全边界与结果可追溯性。本项目把数据资产构建、语义层和安全 NL2SQL 统一到一个可审计的数据工作台。

个人工作：

- 复用并封装原有 DataAssetBuilder，新增 PipelineRuntime，将 CSV 规范化、staging、质量校验、quarantine、发布和血缘编排成可重复执行的管道。
- 使用 SQLite 持久化运行元数据和增量 watermark，只处理成功水位线之后的新记录；无新增数据时返回幂等空运行，避免重复发布。
- 设计管道状态与执行 API，提供源数据行数、暂存/发布/隔离行数、质量结果、血缘、watermark 和运行次数。
- 使用 React + TypeScript 完成中英文 Studio，把数据域、数据源、管道、语义建模、问答分析和运行历史整合到统一界面。
- 将前端 DAG 和可观测卡片替换为真实后端状态，支持从界面发起管道检查并区分首次发布、质量失败和幂等空运行。
- 增加首次发布、watermark 持久化、重复运行不重复写入、质量失败回滚和状态 API 测试，完成 260 项全量回归。

技术难点：

- 一致性：质量与语义契约全部通过后才发布并推进 watermark，避免“数据未发布但水位线已推进”。
- 幂等性：通过已提交 watermark 限定增量范围；同批数据重复执行时发布 0 行，并保留运行记录。
- 安全性：延续 AST 级 SQL 策略和 SQLite 只读执行边界，模型只生成候选 SQL，不能绕过确定性校验。
- 边界复用：API 依赖 application runtime，而不是在路由中重复实现文件和数据库操作。

## 不要夸大的内容

- 当前主要执行边界是 SQLite，不是大规模分布式数仓。
- 当前异步编排是 SQLite + 单进程 Worker，不是分布式调度。
- 当前是受控、本地优先的作品集架构，不是企业级多租户 SaaS。
- 原有 NL2SQL、语义层等能力来自原项目；你的重点贡献是管道运行时、API、真实状态接入、中英文产品化和测试。
