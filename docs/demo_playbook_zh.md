# QueryForge 演示操作手册

> 适用场景：数据开发实习面试、项目答辩、作品集录屏。  
> 推荐时长：标准版 6–8 分钟，精简版 3 分钟。  
> 核心原则：先讲业务问题，再演示技术证据；不要只是逐个点击菜单。

## 1. 演示目标

演示结束后，面试官应当理解：

1. QueryForge 不只是生成 SQL，而是覆盖数据接入、质量、发布、语义和安全查询。
2. 管道具有 watermark、幂等、质量门禁、quarantine、血缘和审计记录。
3. AI 不能绕过确定性的 SQL 安全边界。
4. 你完成的是经授权的二次开发，重点包括双语 Studio、PipelineRuntime、管道 API、真实状态接入和测试。

## 2. 演示前准备

### 环境检查

在项目根目录准备两个终端。

终端 1——启动后端：

    .venv\Scripts\python.exe -m uvicorn queryforge.interfaces.api.app:create_app --factory --host 127.0.0.1 --port 8000

终端 2——启动前端：

    cd web
    npx vinext dev

打开：

    http://localhost:3000/

页面顶部应显示“后端已连接”。当前数据域应为 Anime Streaming。

### 演示前自检

- 中英文切换按钮可用。
- 左侧能看到数据域、总览、数据源、数据管道、语义工作台、问答分析和运行历史。
- 数据管道页面能看到 watermark 2026-01-03。
- “运行管道检查”和“模拟质量失败”按钮可用。
- 问答分析至少准备一个确定性问题。

推荐问题：

- Which anime generated the most watch hours?
- Compare watch completion and merchandise GMV by anime genre.

### 现场表达纪律

- 不说“这是企业级大数据平台”，应说“这是本地优先的作品集参考架构”。
- 不说“全部由我从零开发”，应明确原项目与个人二次开发边界。
- 不把页面上的数字照读一遍，要解释数字证明了什么。
- 失败演示不要放到最后一秒，至少留 1 分钟解释 watermark 为什么不变。

## 3. 标准演示流程（6–8 分钟）

### 第 1 步：项目定位（30 秒）

停留在“数据域”页面。

讲解：

“QueryForge 是一个可治理的 AI 数据分析平台。普通 NL2SQL 更关注能否生成 SQL，这个项目进一步处理原始数据质量、业务语义、安全边界和运行审计。当前示例把数据接入到安全查询串成完整链路。”

指出 Anime Streaming 是当前示例数据域，并说明不同数据域的源数据、指标、语义和运行记录相互隔离。

### 第 2 步：总览业务上下文（30 秒）

点击“总览”。

讲解：

- 当前数据域有自己的数据源、实体、指标和契约。
- 数据域是治理边界，不允许空白新域借用 Anime Streaming 的语义。
- 这是为了避免跨业务上下文生成错误 Join 或错误指标口径。

### 第 3 步：数据源与语义发布门禁（45 秒）

点击“数据源”。

讲解：

- 原始文件进入后先做 profiling。
- 系统可以生成保守的语义初稿，但不能自动作为正式业务口径发布。
- 每个事实实体需要明确 grain 或主键；指标、关系和敏感级别需要人工评审。
- 数据与语义契约作为一个发布单元，任意一侧失败都会阻止发布。

不要现场上传陌生大文件，以免把演示时间消耗在等待和解释非核心问题上。

### 第 4 步：正常管道与 DAG（60 秒）

点击“数据管道”。

从左到右介绍：

1. Extract：读取 anime_watch_events.csv。
2. Validate：检查结构、必填字段、唯一键和语义质量规则。
3. Transform：数据进入 staging，而不是直接写服务表。
4. Publish：门禁通过后发布到 fact_watch_events。

解释四个健康指标：

- Freshness SLA：是否已有成功持久化的 watermark。
- Quality gate：质量规则通过数量。
- Lineage coverage：源、暂存和目标之间的血缘。
- Incremental watermark：当前成功处理到的位置。

### 第 5 步：幂等空运行（45 秒）

点击“运行管道检查”。

等待运行结束后指出：

- 数据源仍然是 5 行。
- 如果没有比 2026-01-03 更新的数据，发布行数为 0。
- watermark 前后不变。
- 这不是失败，而是幂等空运行。

讲解：

“重复执行不会制造重复数据。输入范围由最后一次成功 watermark 决定，运行本身仍然有审计记录。”

### 第 6 步：质量失败和 quarantine（90 秒）

点击“模拟质量失败”。

系统会构造一条日期为 2026-01-04、但缺少 anime_title 的受控异常记录。

重点展示：

- 状态从健康变为质量门禁阻断。
- 暂存 1 行、隔离 1 行、发布 0 行。
- 页面展示缺失必填字段的原因和原始问题记录。
- watermark 仍然是 2026-01-03。
- 运行历史新增一条 BLOCKED 记录。

讲解：

“异常数据比旧 watermark 更新，所以会进入本次增量范围；但必填字段检查失败，异常行进入 quarantine，发布被阻止，watermark 不推进。修复后仍能重新处理这条数据。”

补充技术点：

“发布状态可以回滚，但审计证据不能随回滚消失。因此我把不可变运行证据和可回滚发布状态分开持久化。”

### 第 7 步：语义工作台（60 秒）

点击“语义工作台”。

选择一个事实实体，介绍：

- Entity：业务对象。
- Grain：一行数据代表什么。
- Dimension：分析切片。
- Metric：受治理计算口径。
- Relationship / Join Path：允许的连接路径。
- Owner / Sensitivity：负责人和敏感级别。

讲解：

“物理 schema 只说明有哪些字段，无法说明活跃用户、收入、完成率等业务口径。语义层把这些口径变成可评审、可测试的版本化配置。”

### 第 8 步：问答分析与 SQL 安全（60 秒）

点击“问答分析”，输入预先准备的问题并执行。

展示：

- 自然语言问题。
- 生成 SQL。
- 查询结果。
- 解释或 Trust Trace。

讲解：

“模型只生成候选 SQL。SQL 在执行前必须经过 AST 解析、只读语句限制、表列范围、函数和复杂度预算；最终通过 SQLite 只读连接执行。安全边界由确定性代码控制，不依赖提示词。”

### 第 9 步：运行历史收尾（30 秒）

点击“运行历史”或回到数据管道运行历史区域。

总结：

“一次查询或管道运行不仅返回结果，还保留 run id、状态、行数、watermark、失败原因和证据。这使问题能够追踪，而不是把 AI 当成不可解释的黑盒。”

## 4. 三分钟精简版

1. 20 秒：项目定位——数据管道 + 语义层 + 安全 NL2SQL。
2. 30 秒：数据域和语义治理边界。
3. 40 秒：数据管道 DAG 与 watermark。
4. 35 秒：运行一次，展示幂等发布 0 行。
5. 45 秒：模拟失败，展示 quarantine 和 watermark 不推进。
6. 30 秒：展示语义层和 AST 只读安全边界。
7. 20 秒：说明个人贡献和 260 项回归测试。

## 5. 录屏版建议

- 浏览器缩放保持 90%–100%，关闭无关标签和通知。
- 分辨率建议 1920×1080。
- 鼠标停留在要解释的指标上，不要快速来回移动。
- 先录一段无声音操作，确认没有按钮卡住，再正式录制。
- 正式视频控制在 5 分钟左右，字幕只突出关键词。
- 首页 5 秒内出现项目名称和一句话定位。
- 结尾显示 GitHub 地址、技术栈和个人贡献。

## 6. 演示故障兜底

### 页面显示后端离线

检查 8000 端口的 API 是否运行，然后刷新页面。不要现场重新安装全部依赖。

### 管道按钮不可用

确认当前数据域是 Anime Streaming，且示例数据源存在。

### 失败演示后页面仍显示旧状态

刷新数据管道页面；状态来自后端持久化数据库，不依赖浏览器本地状态。

### 模型 API 不可用

继续演示管道、语义层和 SQL 安全。说明项目支持离线确定性样例，在线模型不是数据治理链路成立的前提。

### 面试官要求看代码

按顺序打开：

1. queryforge/application/pipeline_runtime.py
2. queryforge/data_assets/pipeline.py
3. queryforge/interfaces/api/app.py
4. tests/test_pipeline_runtime.py
5. web/app/page.tsx

先讲边界与数据流，再进入具体函数，不要从文件第一行逐行阅读。

## 7. 演示结束后的主动总结

“当前版本已经证明了增量、幂等、迟到数据回看与 Upsert、质量阻断、原子发布、持久化异步状态机、审计证据和安全查询。它当前的边界是 SQLite、本地单进程 Worker 和受控部署。下一步我会优先增加 PostgreSQL adapter、外部任务队列、跨实例租约和复合游标，把本地参考架构推进到更接近生产的数据平台。”
